{% extends 'base.html' %} {% block title %}Members{% endblock %} {% comment %} The page an administrator spends the most time on, so it is dense on purpose. Paging through three screens to find one player is worse than a slightly crowded table. FOUR THINGS FIXED IN THE MIGRATION, all of them live bugs: 1. INVISIBLE TABLE HEADER. The header row was `style="background:var(--chess-dark);color:white"`, and --chess-dark has not existed since the redesign deleted the inline stylesheet in 72e42d0. An undefined custom property makes the declaration invalid at computed value time, so the background fell back to transparent and left white text sitting on a white card. The column headings have been unreadable. Same story for --chess-accent on the ELO column. 2. THE ANNOUNCEMENT COULD NOT BE SENT WITHOUT JAVASCRIPT. The send control was type="button" calling confirmSend(), so with scripts off it did nothing at all. It is a real submit button now and the confirmation hangs off the form's submit event, which means the worst case is that the mail goes without asking twice rather than never going. 3. THE COMPOSE PANEL WAS A BOOTSTRAP COLLAPSE. Dropping Bootstrap would have left it permanently open. It is a details element now, which needs no JavaScript and no library. 4. ACTIONS WERE UNLABELLED GLYPHS. Deactivating a member was a button reading U+2298, resetting somebody's rating was U+27F3. Both fall back to empty boxes on the handsets this is opened on, so an administrator was choosing between two blank buttons, one of which wipes a rating history. They are words now. {% endcomment %} {% block content %}
